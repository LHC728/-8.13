# 2016—2018 年国赛 B 题官方展示论文的写作结构与表现手段

> 研究对象：2016 B022、B044；2017 B104、B264；2018 B217、B334，共 6 篇中国大学生在线官方展示论文、178 个 PDF 页面。  
> 研究目的：不再重复“这篇用了什么模型”，而是分析它如何把题意、假设、模型、算法、结果和验证组织成可阅读的竞赛论文。  
> 证据口径：【论文呈现】表示 PDF 中直接可见的章节、图表、算法步骤或作者表述；【结构判断】表示本次对其论证效果的评价，不冒充作者或官方专家意见。

## 2. 先给结论：六篇论文的结构共性与差异

### 2.1 它们并不都采用“基线—改进模型”模板

【论文呈现】六篇中至少可辨认出五种模型叙事：

1. **层级串联**：B022 用“指标体系→交通仿真→综合评价→异常解释”串联多个模型。
2. **实验递进**：B044 围绕延误差，不断改变道路长度、节点数、流量与信息情景。
3. **题问递进**：B104、B264 把第一问的定价规则带入第二问，再增加打包和新项目。
4. **多基线比较**：B217 同时比较就近、FIFO、HRRN，再尝试自适应随机搜索。
5. **理论—算法—界限**：B334 先给工作循环、系统均衡和 CNC 满载上限，再构造状态转移与求解算法。

【结构判断】因此，优秀论文的共性不是“必须有两个模型”，而是读者始终能回答三个问题：当前这一节在解哪个困难？比前一步增加了什么信息？有什么证据说明它有效？

### 2.2 六篇的典型章节骨架

| 组件 | 六篇中的主要做法 | 写作上的真正作用 |
|---|---|---|
| 摘要 | 几乎全部按问题一、二、三分段，同时写方法名和数值结果 | 提前给出论文的“路线图＋结果表” |
| 问题重述 | 压缩原题背景和小问 | 建立论文自足性，但不应复制原题 |
| 问题分析 | 多数论文逐问说明拟用的指标、模型与求解路线 | 把“为什么这样做”放在公式之前 |
| 假设与符号 | B044 额外解释假设可行性；B044、B217 的符号表较注重单位 | 界定模型适用范围，减少公式重复解释 |
| 建模与求解 | 一部分论文按小问组织，B334 则把模型家族集中建立后再集中写算法 | 让公式、算法和问题对应，避免“模型名单” |
| 结果 | 表格给出核心数字，图形解释过程、空间或参数规律 | 表格承担“精确证据”，图承担“机制证据” |
| 验证 | 敏感性、控制变量、多规则比较、布局穷举、理论上界等 | 不是“再跑一次代码”，而是换一种证据口径 |
| 评价与改进 | 6 篇均有，但深度差异很大 | 应与假设、误差和已观测失败直接对应 |
| 附录 | 主要放原始代码、部分数据表和额外调度结果 | 支持复现，但不应反客为主 |

### 2.3 实际上最稳定的优秀写法

【结构判断】跨六篇看，最值得学的不是任何一篇的完整目录，而是下面这个局部循环：

> 小问目标 → 关键困难 → 必要假设 → 变量与机制 → 数学模型 → 求解算法 → 核心结果 → 一种独立检查 → 本问小结

一篇论文可以没有多个模型，但不应跳过“关键困难”和“独立检查”。公式与结果之间的这两座桥，比多一个高级模型名更能提高说服力。

## 3. 逐篇写作结构卡片

### 3.1 2016 B022：“评价—仿真—反例”闭环

#### 结构路线

【论文呈现】正文大致按“摘要→问题重述/分析→假设/符号→问题一的六指标投影寻踪评价→问题二的道路机理和元胞自动机→问题三的多场景仿真、综合排序、敏感性和 Braess 异常解释→问题四建议→模型评价/推广→代码附录”展开。正文约到第 21 页，第 22—26 页为 MATLAB 代码。

#### 摘要手段

- 【论文呈现】摘要占满首页，按四个问题分段；每段都说明所用模型，第一、三问还直接报告投影方向、投影评价值和敏感性幅度。
- 【结构判断】优点是读者首页就能看到完整方法链和主要结果；缺点是过密，六组投影方向不是摘要中最需要的信息，可以留给正文。

#### 前置章节

- 【论文呈现】“问题重述”与“问题分析”分开；分析已经预告了定性/定量指标、微分方程、元胞自动机和场景设计。
- 【结构判断】这个“先给路线后给公式”的顺序是可取的；但符号表过于简短，后文又新增大量符号，未完全承担“全局字典”功能。

#### 模型递进与表现

- 【论文呈现】第一问先定义六个指标，再标准化、投影寻踪和模拟退火求权重；第二问先画总求解流程图，然后分直行、T 形、入闸式三类道路写机理，最后统一到元胞自动机。
- 【论文呈现】第三问先画方形/三角形小区及开口方案，再大量展示黄蓝仿真快照，紧接着用指标表和投影值表压缩结果。
- 【结构判断】图的职责分配相对明确：流程图解释“怎么算”，道路图解释“算什么”，仿真快照解释“发生了什么”，表格说明“结果多少”。这种角色分工值得模仿。

#### 验证、结尾与附录

- 【论文呈现】将转向/变道概率作扰动，用表格和折线图呈现投影值变化；对新增道路后评价反而变差的情况，单列 Braess 悲论小节进行解释。
- 【结构判断】“不删异常值，而是给异常安排一个论证位置”是本篇最强的写作手段。但这仍是模型内部解释，不等于现实交通已经验证。
- 【论文呈现】没有单独的“结论”章，第四问的建议和“优点—缺点—推广”共同担任收尾。附录连续放置 5 页原始 MATLAB 代码。
- 【结构判断】正文已经有流程图，附录代码可支持复现；但没有输入输出文件、随机种子和运行说明，读者仍难以一键重现。

#### 值得模仿 / 不应照搬

- **值得模仿**：多层模型每层都有明确输入输出；图表职责分明；主动展示敏感性和反直觉情形。
- **不应照搬**：为了显得丰富而堆叠评价、微分方程、元胞自动机、模拟退火等名词；用同一仿真器的输出反过来证明仿真器现实正确。

### 3.2 2016 B044：“主指标—模块化仿真—控制变量”实验叙事

#### 结构路线

【论文呈现】结构为“摘要→问题重述→问题分析→假设及可行性→符号→延误差指标→四模块元胞自动机及路径改进→两类小区的控制变量实验→规划/交管建议→模型评价与改进→附录代码”。正文与参考文献到约第 19 页，第 20—28 页为代码。

#### 摘要与前置章节

- 【论文呈现】摘要同样按四问分段，但其中最明确的主线是“开放前后平均延误之差”。后文几乎所有实验都回到这个因变量。
- 【论文呈现】假设后单列“假设可行性”，解释为什么可忽略混行、出入口信号等。符号表分“符号、含义、单位”三列。
- 【结构判断】这是六篇中最明确地让假设接受质询的一篇。“假设内容＋合理性＋可能影响”比只列假设更有说服力；但文中的“可行”不能替代实测标定。

#### 模型递进与图表

- 【论文呈现】第二问将模拟器分为车辆进入、普通道路、无信号交叉口、有信号交叉口四个子模型，用 Step 1—Step 6 描述状态转移，再将随机路径选择改为基于信息的路径代价函数。
- 【论文呈现】第三问先列“结构、内部道路长度、进入概率/流量”的因素—变量表，然后分“无分合流”和“有分合流”两类结构做扫参。
- 【论文呈现】页面上大量使用三维小区示意图、多条时间序列、小多图和三维曲面。SPSS 相关性表被放在相应曲线之后，而不是单独堆在章末。
- 【结构判断】“先图形观察，后统计量化”是比较好的阅读顺序。但部分曲线只是换参数重复画图，图太多时会把主结论淹没；更好的方式是选一张代表图，其余结果用汇总表或支撑材料呈现。

#### 结果、评价与附录

- 【论文呈现】每一组实验图后立即用一段话说明趋势、正负效应和可能机制，不等到全章末尾统一解释。问题四将建议分成城市规划部门和交通管理部门两个对象。
- 【结构判断】按决策对象组织建议，比“应合理规划”式空话好。但统计相关来自自己设定的仿真参数，不应用显著性语言强化为现实因果结论。
- 【论文呈现】附录从第 20 页起连续放置 9 页 MATLAB 函数，包含初始化、红绿灯状态转移、路径选择和作图。
- 【结构判断】函数化代码与正文的四模块设计一致，这是好的“论文—代码同构”；但用大量论文页面展示原始代码并不高效。

#### 值得模仿 / 不应照搬

- **值得模仿**：一个清晰主指标；假设可行性；模块化仿真；控制变量表；每图后就地解释；按决策对象写建议。
- **不应照搬**：为每个参数都画多张相似曲线；在模拟数据上做显著性检验后，把结论直接推广到现实交通。

### 3.3 2017 B104：“地图视觉化—特征回归—方案对比”数据故事

#### 结构路线

【论文呈现】结构为“摘要→问题重述→逐问分析→三条基本假设→符号→问题一的地图/聚类/回归→问题二的信誉特征与博弈定价→问题三的三点打包→问题四的新项目迁移→模型优缺点/推广→参考文献→自制地图、代码和部分 Excel 表”。正文到第 18 页，第 19—25 页为附录。

#### 摘要与章节组织

- 【论文呈现】摘要逐问报告地图分区、三个定价特征、新旧总价与“预计完成率”、打包后提升和新项目结果。其结果数字非常突出。
- 【结构判断】摘要的可读性强，但它使用“完成率上升”这种强结论，正文却没有真实实施标签或独立测试集。优秀摘要不仅要有数字，还要用词区分“观测完成率”和“模型预估完成率”。
- 【论文呈现】每个问题在第二章已有一段分析，正文再用“模型的建立—模型的求解”组织。这种双层结构导航清楚。

#### 视觉表现与结果叙述

- 【论文呈现】论文先将任务和会员放到谷歌地图，再给 K-means 聚类散点图，后续使用回归拟合图、环形/饼图、打包流程图、打包空间分布图和新项目聚类图。
- 【结构判断】地图不是装饰：它直接导向区域中心、偏僻度和 1.5 km 邻域特征，属于“从图中产生变量”。这是值得学的图文关系。
- 【结构判断】方案前后用饼图呈现 62.5% 与 89.5%，视觉冲击强，但不如“完成数/总数＋绝对提升百分点＋总价变化”的统一对照表精确，也隐去了不确定性。

#### 算法、验证与收尾

- 【论文呈现】打包算法在正文先用 3 条策略说明，后面配一张“遍历—判断—打分—选组—标记”流程图，再给打包结果图。这比把 MATLAB 循环直接搬入正文更适合阅读。
- 【论文呈现】没有专门的敏感性、留出检验或外部验证章；“新旧价格与预计完成率”的比较就是主要证据。模型评价中承认仅用附件数据、无法进一步评估准确度。
- 【结构判断】本篇的故事比证据强。由图发现特征、由特征定价、由定价引出打包，阅读体验顺畅；但“估计完成率”来自自定义规则，结论语气应降级为“模型内部评估改善”。
- 【论文呈现】附录包含自制地图链接、8 个 MATLAB 脚本和三份附件的部分处理表。这是六篇中少数将“代码＋数据表样例”同时放入附录的论文。

#### 值得模仿 / 不应照搬

- **值得模仿**：地图产生特征；按小问近距离组织“建立—求解”；算法先写规则再画流程；结果在摘要中直接量化。
- **不应照搬**：用饼图替代精确对照表；将模型自产的“预计完成率”写成已实现的平台效果；把“图看起来合理”当作模型验证。

### 3.4 2017 B264：“规则定价—满意度边—最大流分配”运筹结构

#### 结构路线

【论文呈现】结构为“摘要→问题背景/数据/需求→假设与符号→经纬度转距离→问题一的指标和分段定价→问题二的地区修正、满意度和最大流分配→问题三的二次打包→问题四的缺失特征迁移→模型评价→参考文献→算法说明与 C++ 代码”。正文到第 18 页，第 19—25 页为附录。

#### 章节组织与模型递进

- 【论文呈现】将“数据预处理”单独提为第 3 章，在所有小问之前统一处理经纬度距离。这与 B104 把地图/聚类放进问题一不同。
- 【结构判断】如果一项处理会被后续多问共用，单列章节更好；如果它只为某一问服务，放在该问内更紧凑。B264 这里的单列是合理的。
- 【论文呈现】第四章把会员密集度、任务集中度、难度各自定义后，用对应表转换成定价修正值，并用具体任务号做局部示例。第五章不仅改价，还把“会员是否愿意做任务”转成二分图的边，再建最大流。
- 【结构判断】这个写法的优点是把“定价”和“容量分配”分成两层：前者定义可行边，后者在边上优化。层间接口明确，比一个大黑箱直接输出分配更易审查。

#### 数学与算法的呈现

- 【论文呈现】最大流模型在正文中先集中定义目标函数和五组约束，再给完整规划式；紧接着用 Step 1—Step 4 写外层参数搜索与 Dinic 求流程程。
- 【论文呈现】附录不是立即贴代码，而是先用一页说明随机搜索、任务—会员网络和源汇点，配一张最大交易数示意图，然后再放 C++ 代码。
- 【结构判断】“模型完整式→人类可读步骤→网络示意→源码”是六篇中较成熟的算法表达层次。不足是步骤没有给运行时间、重复次数、随机种子和最优性差距。

#### 结果表、验证与收尾

- 【论文呈现】结果以表格为主：旧价/新价、旧完成状态/新完成状态，再汇总总定价、平均定价和完成率。第三问把原方案、问题二方案和打包方案放在一张三行对照表中。
- 【结构判断】这类对照表比饼图更适合优化题，因为它同时保留价格代价和完成收益，可以防止只报一个好看指标。
- 【论文呈现】将价格总上限从约 5.6 万扫到 7.6 万，绘制预算—最大完成量曲线，并解释边际收益分段。
- 【结构判断】这是本篇最有用的敏感性表现，因为它对应平台决策，而不是为了凑“灵敏度分析”而扰动无关参数。但所有完成率仍是满意度规则内生的预计值，不是现实反事实。
- 【论文呈现】结尾仅有“优点/缺点”和 2 篇参考文献，没有独立结论章。

#### 值得模仿 / 不应照搬

- **值得模仿**：公共预处理独立成章；定价与分配分层；目标与约束集中呈现；算法有步骤、网络图和代码三级表达；用对照表同时报告收益与代价。
- **不应照搬**：可行边由任意满意度阈值产生却不做校准；只因 Dinic 求得精确最大流，就把整个现实方案称为精确；在不报告时间和重复结果时宣称启发式“精度高、运算快”。

### 3.5 2018 B217：“形式化规划—可执行策略—多基线”长篇技术报告

#### 结构路线

【论文呈现】正文只设五个顶级章：“问题重述→问题分析→假设与符号→模型建立/求解/分析→评价与改进”。第 4 章内再按单工序、双工序、故障三种情况展开；正文到第 22 页，第 23—45 页为代码附录，附录页数超过全文一半。

#### 摘要与技术叙事

- 【论文呈现】摘要按三种情况分段，报告三组参数下的成品数、256 种工序分配的遍历、蒙特卡洛学习结果和故障后效率下降。摘要末尾还单写“本文的亮点在于”。
- 【结构判断】直接说亮点能帮助评阅快速定位，但亮点应是“有什么新机制或新证据”，不应只是“综合了若干高级名词”。本篇的实质亮点其实是三种调度基线和 256 种布局遍历。

#### 正文层次

- 【论文呈现】每种情况基本遵循“作业流程→调度规划模型→求解算法→结果检验与分析”。单工序先用大量 0-1 变量刻画移动、上下料、清洗和唯一性，再转向仿真策略。
- 【结构判断】形式化规划在这里不是为了强行交给求解器，而是当作约束清单；然后仿真策略作为工程求解。这种“数学完整性与计算可行性分工”是值得模仿的。
- 【论文呈现】就近、FIFO、HRRN 先用文字定义时间代价/等待/响应比，再共用同一张算法流程图。双工序也先修正规划约束，后复用三原则算法框架。
- 【结构判断】对共享框架只画一张流程图，再用一个“策略函数”区分基线，比复制三份流程图好。

#### 结果表现与验证

- 【论文呈现】单工序先用一张 3×3 成品数表比较三组参数和三条原则，再给局部调度时间表。双工序遍历 256 种 CNC 类型布局，用表格给出每组最优布局和原则。
- 【结构判断】这个比较口径很好：同一参数、同一时段、同一成品数目标，不同规则横向并列；布局能穷举时全穷举，不用不必要的启发式。
- 【论文呈现】蒙特卡洛学习部分按 Step 0—Step 6 定义学习样本、概率区间、随机投点、更新和终止，然后用“初始原则/学习前最优/学习后最优”表和频数热力图呈现。
- 【结构判断】算法说明比较完整，但“学习”证据并不完整：它没有独立测试，而且第三组的学习结果仍未超过就近基线。论文应更明确地写“仅改善了某两个初始策略，未提高总体最优值”。
- 【论文呈现】故障情景用前后对照表报告故障物料数和成品数下降，但未报告多随机种子的平均值、标准差或分位数。

#### 收尾与附录

- 【论文呈现】正文末尾仅一页模型优点、缺点与改进；参考文献 5 项，其中含 CSDN 博客。附录 23 页分 Case1、Case2、Case3 展示 C++/MATLAB 代码。
- 【结构判断】附录按情况分组与正文同构，但原始代码占比过大，不是值得照搬的版面策略。正文应保留状态、策略、伪代码和复现信息，完整代码更适合放可运行支撑材料（具体以当年格式为准）。

#### 值得模仿 / 不应照搬

- **值得模仿**：规划模型当约束字典；多基线同口径比较；可穷举的结构变量完整穷举；公用算法框架只画一次；算法用步骤、流程图、结果表和热力图分层表达。
- **不应照搬**：数学约束铺陈过长而没有小例子；把自适应随机搜索简单称为“机器学习”；随机故障只展示一次实现；用超过半数页面展示原始代码。

### 3.6 2018 B334：“原则与证明—状态图—上界”证据链

#### 结构路线

【论文呈现】本篇是六篇中唯一在摘要后给详细目录的论文。正文结构为“背景与重述→假设→符号→问题分析→模型建立与三类状态转移图模型→三类求解算法→结果及上界评价→评价与改进→参考文献”。正文到第 20 页，第 21—29 页为 C++ 和 Python 代码。

#### 摘要、分析与原则

- 【论文呈现】摘要不仅报告三组成品数，还先介绍 RGV 工作循环、系统均衡和 CNC 满载上限，说明这些理论将用于建模与评价。
- 【论文呈现】问题分析占约两页，先把 CNC 抽象为任务队列，再解释为什么用事件时间而不是逐秒离散，同时预告状态向量、转移矩阵、分阶段决策和可用的求解算法。
- 【结构判断】它的“问题分析”真正承担了方法选择论证，而不是换句话复述原题。这是六篇中值得优先模仿的分析写法。
- 【论文呈现】模型章的开头连续给出“定义 1—证明 1—定义 2—原则—定义 3”，建立最短循环、系统效率均衡和满载上限。
- 【结构判断】先讲可证明的系统规律，再写启发式规则，能让算法不显得任意。但原则的成立条件必须与实际使用情景一起写，否则“有证明”也可能被过度推广。

#### 模型、算法与视觉化

- 【论文呈现】“基本状态转移图→带工序约束→带故障风险”三个模型用共同状态向量和转移语言递进。新模型只增加 CNC 类型向量、故障因子和相应约束，没有每问重新起灶。
- 【结构判断】这是“模型家族”的好写法：先定义稳定核心，再列每个扩展所增的状态、约束和评价函数。读者可直接看到小问递进关系。
- 【论文呈现】求解部分与模型部分分开。先承认完整状态树复杂度过高，再给“优先选前两台、优先代价小、并列时选更早结束、始终可行”的四条搜索原则，后面再写决策过程。
- 【结构判断】模型与算法分开适合本篇，因为三个模型共享算法思想。若每一问的模型和算法差异很大，则就地组织更好；不能机械照搬。
- 【论文呈现】主要图形不多，但职责集中：多队列甘特式示意图、状态转移图、CNC 比例—产量曲线、RGV 运动路线/操作时间图，以及未实施的遗传算法改进流程图。

#### 结果验证、透明性与内部错误

- 【论文呈现】结果表将理论满载上限、求解值和所谓“结果偏差率”并列。这比“搜索很多次没找到更好值”更接近最优性证据。
- 【结构判断】这是六篇中最强的结果验证框架之一，因为评价标准在算法之前由理论得到，不依赖同一启发式的输出。
- 【论文呈现】附录 C++ 代码开头明确注明：总时长 1000 s 时能较快给答案，8 h 时因复杂度高无法给出答案，需调整 `tot_t`。
- 【结构判断】这条注记非常值得模仿：它清楚区分了小规模精确搜索与 8 h 启发式结果，没有伪装全局最优。最好将这种计算限制同时放入正文的验证小节，而不只藏在附录。
- 【结构判断，算术可直接复核】论文把偏差率定义为 `|A-U|/U`，但表中 382 与 384 对应 0.9948，实际是 `382/384`，不是偏差率约 0.0052；其他列还有额外录入/计算不一致。这说明“有很强的验证设计”不等于“验证表一定没错”，最后还需要公式—表格自动对账。
- 【论文呈现】模型评价将优点、缺点、改进分成三节，并把状态空间指数增长和某些指导原则的条件性写入缺点。改进节提出 Messy GA 并给流程图，但没有把它伪装成本文已完成结果。

#### 值得模仿 / 不应照搬

- **值得模仿**：长文用目录导航；问题分析解释为什么用事件离散；原则与成立条件先于启发式；一个基础状态模型逐问扩展；理论上界验证；明确披露精确搜索的规模限制。
- **不应照搬**：把“求解值/上界”误标为“偏差率”；在随机故障下只给一次运行；改进节仅画一个高级算法流程就宣称可提高效果。

## 4. 专项深挖：优秀论文如何“写”，而不仅是如何“算”

### 4.1 标题：对象、结构和方法之间的平衡

【论文呈现】B022、B044、B104、B334 标题直接描述问题；B264 加“基于优化理论”；B217 将多原则、蒙特卡洛与 RGV 动态调度同时写入标题。

【结构判断】实用的标题公式是“对象/任务＋一个真正区分论文的结构”，例如“基于事件状态图与上界验证的 RGV 动态调度”。不要把全部工具名塞入标题，也不要只复制赛题名而不告诉读者你的特征。

### 4.2 摘要：不是方法名单，而是“问题—动作—结果—证据”

六篇的共同优点是摘要按小问展开，且普遍有数字。但更好的摘要不应复制“针对问题一……针对问题二……”模板，而应使每一段包含：

1. 问题的核心矛盾，而不是照抄小问；
2. 为这个矛盾增加的状态、机制或约束；
3. 实际使用的模型/算法；
4. 最重要的数值或规律；
5. 该数值是如何验证的，或它只是什么性质的估计。

可直接使用的摘要句型是：

> 针对 X 中的 Y 难点，我们用 A 表示……，建立 B 模型，并用 C 求解。在相同约束下，方案相对基线将指标由 m 改善到 n；该结果经过 D 检查，但仅适用于 E 条件。

### 4.3 问题重述与问题分析：两节不应做同一件事

【结构判断】对六篇的比较表明：

- **问题重述**应回答“输入、输出、对象和小问关系是什么”；
- **问题分析**应回答“难点在哪、将怎样简化、用什么证据判定成功”。

B334 对事件时间离散和状态转移的预告，B044 对正负效应与分合流情景的区分，都属于真正的分析。仅把“问题要求我们建模”换成“所以我们需要建模”，不产生新信息，应删除。

### 4.4 假设与符号：从格式节变成风险清单

一个好假设应连续写四件事：

| 字段 | 要回答的问题 | 可用表达 |
|---|---|---|
| 假设 | 具体省略了什么？ | 不考虑……/认为…… |
| 理由 | 为什么在本问可以这样做？ | 题目范围、时间尺度、数据限制 |
| 影响 | 这会把结果推向哪个方向？ | 可能高估/低估…… |
| 检查 | 用什么情景验证该假设不致命？ | 极端情景、参数扰动、去除假设的扩展模型 |

符号表要求不是“越多越专业”，而是正文中每个重要符号都能找到唯一定义。至少包含符号、意义、单位/取值域，必要时再加数据来源。B044 的单位列值得模仿；B022 那种只列少数初始符号、后文不断新增的做法不足。

### 4.5 公式的写作手段：先语义，后形式

从 B217 和 B334 可提炼一个实用顺序：

1. 先用一句话写这个公式要防止什么不可行行为；
2. 定义变量和索引范围；
3. 给出公式；
4. 翻译回业务含义；
5. 用一个极小例子或边界情形说明公式行为。

B264 在分段定价后用具体任务号代入，是第 5 步的雏形。B217 的长公式组虽完整，但缺少更多小规模时序示例，会提高阅读成本。

### 4.6 图表：一张图只应承担一个论证任务

| 图表类型 | 样本中的好用法 | 常见失败 | 改写原则 |
|---|---|---|---|
| 流程/状态图 | B022 总仿真流程；B217 单/双工序流程；B334 状态转移 | 与代码逐行等价，节点太多 | 只保留状态、决策、循环和终止 |
| 空间图 | B104 地图直接产生邻域特征 | 地图只用作背景装饰 | 正文必须说“从这张图得到了哪个变量/假设” |
| 场景示意图 | B022/B044 分形状、分合流结构 | 美观但没有标输入、路径和边界 | 用统一编号与正文变量对齐 |
| 参数曲线 | B044 控制变量；B264 预算—完成量 | 多张相似曲线堆叠 | 选代表图，其余用汇总表/分位带 |
| 精确结果表 | B264 新旧方案；B334 上界/求解值 | 公式、表头和数值不同口径 | 表必须由结果文件自动生成，不手填 |
| 饼图 | B104 用于快速展示完成/未完成 | 难以精确比较，隐藏样本量和不确定性 | 两方案优先用并列表或点图 |

图注不应只写“仿真结果”。更好的题注可写“固定流量下内部道路长度对延误差的影响”；图后第一句必须给出读者应观察的趋势，第二句再解释机制，第三句说明它是否改变决策。

### 4.7 算法与伪代码：需要让读者能重新实现，不需要让读者在正文调试

六篇中最可取的算法表达层次是：

1. **接口**：输入数据、输出指标、状态和策略是什么；
2. **核心规则**：如 B217 的就近/FIFO/HRRN，B334 的转移代价与可行性检查；
3. **步骤或伪代码**：给循环、更新、终止与返回值；
4. **流程图**：只在存在多分支、多状态时使用；
5. **计算性质**：复杂度、精确/启发式性质、随机性、终止条件；
6. **复现信息**：软件版本、参数、种子、运行时间、结果文件；
7. **完整代码**：放支撑材料，正文只引用文件和函数名。

B264 的“规划式—步骤—网络图—代码”、B334 的“精确搜索规模限制说明”是正面样例。B022/B044 以及 B217 巨量原始代码附录不适合直接搬到当前论文主体。

### 4.8 结果验证：强证据必须来自不同口径

从六篇可构造一个从弱到强的验证梯子：

| 层级 | 验证方式 | 六篇中的例子 | 能证明什么 |
|---:|---|---|---|
| 1 | 结果可视化/局部常识 | B104 地图与拟合图 | 能发现粗大错误，不能证明最优或因果 |
| 2 | 控制变量/参数扫描 | B044 道路长度、流量；B264 预算上限 | 能描述模型内部机制和阈值 |
| 3 | 敏感性/极端情景 | B022 概率扰动与 Braess 异常 | 能检查结论对参数和直觉的稳定性 |
| 4 | 多基线同口径比较 | B217 就近/FIFO/HRRN | 能证明新策略是否真有增益 |
| 5 | 小规模穷举/精确解 | B217 的 256 种布局；B334 1000 s 精确搜索能力 | 能检查启发式和实现边界 |
| 6 | 理论上下界/保证 | B334 CNC 满载上限 | 能给出最优性差距的参照 |
| 7 | 外部数据/留出集/真实试验 | 本六篇普遍不足 | 才能评估现实泛化效果 |

高质量论文至少应同时拥有两个不同口径的层级，例如“基线比较＋小规模精确解”或“敏感性＋理论上界”。如果实现程序、结果生成和验证全部共用同一个函数，它们可能同时错。

### 4.9 结果表述：“好”必须拆成收益、代价和证据强度

对优化方案，推荐的结果表至少包含：

| 项目 | 基线 | 改进方案 | 变化 | 证据口径 |
|---|---:|---:|---:|---|
| 核心收益 |  |  |  | 观测/模拟/预测 |
| 总成本/预算 |  |  |  | 同一费用口径 |
| 约束违反 |  |  |  | 独立可行性检查 |
| 运行时间 |  |  |  | 相同硬件/软件 |
| 随机稳定性 |  |  |  | 多种子均值/分位数 |
| 距上下界差距 |  |  |  | 界的假设和方向 |

B264 同时报总价、平均价和完成率，B334 同时报求解值与上界，都接近这个思路。B104 的饼图和 B217/B334 的单次故障结果，则遗漏了样本量、方差或证据性质。

### 4.10 优缺点、结论和建议：不要用通用套话收尾

【论文呈现】六篇均有“模型评价/优缺点/改进”，但均没有很强的独立“结论”章。2016 年两篇用第四问政策建议收尾；2017—2018 年多用模型评价收尾。

【结构判断】没有“结论”标题不是必然缺点，但最后一页应完成三件事：

1. 回答每个小问的最终数值/规律；
2. 说明该结论是观测、模拟、预测还是理论保证；
3. 给出一个最重要的限制和一个可操作的建议。

“模型精度高、通用性强、运行时间短”只有在正文分别有精度数据、跨情景测试和运行时间时才能写。B334 把状态空间指数增长和原则成立条件写入缺点，比通用套话更强。

### 4.11 附录与支撑材料：复现不等于把源码截图填满

| 论文 | 正文/参考文献结束约在 | 附录页码 | 附录主要内容 |
|---|---:|---:|---|
| B022 | 21 | 22—26（5 页） | 投影寻踪、元胞自动机 MATLAB 代码 |
| B044 | 19 | 20—28（9 页） | 模块化仿真、红绿灯、路径与作图函数 |
| B104 | 18 | 19—25（7 页） | 地图链接、MATLAB 脚本、部分 Excel 表 |
| B264 | 18 | 19—25（7 页） | 算法说明、最大流网络图、C++ 代码 |
| B217 | 22 | 23—45（23 页） | 三种 Case 的 C++/MATLAB 原始代码 |
| B334 | 20 | 21—29（9 页） | 小规模剪枝搜索 C++、事件仿真 Python |

推荐的现代支撑材料是一个“可运行包”，而不是代码页面：

- `README`：运行环境、命令、输入输出与预计时间；
- `data_raw/` 和 `data_processed/`：原数据与处理结果分开；
- `src/`：模拟器、策略、验证器分离；
- `tests/`：正常、边界、反例和小规模精确测试；
- `results/`：论文所有图表的唯一数据源；
- `environment`：依赖版本、随机种子和求解器配置。

## 5. 为你们队伍提炼的 B 题论文写作模板

下面不是将六篇目录求并集，而是对它们有效部分的重组。

### 5.1 第一页：摘要

1. 一句话定义对象、决策目标和主要困难。
2. 每个小问用“新增的信息/机制→模型→求解→核心结果”一段。
3. 单列一句验证：上界、小例子、留出集、敏感性或多随机种子。
4. 末句只写真正的创新与适用范围。

### 5.2 前置部分

1. **问题理解**：对象、输入、输出、约束、小问依赖图。
2. **数据审计/预处理**：行列数、缺失、异常、单位、时间窗口、坐标转换；被多问共用时独立成章。
3. **问题分析**：每问一行“难点—模型—算法—验证”路线表。
4. **假设与符号**：假设附理由和影响；符号含单位/取值域。

### 5.3 小问正文的固定单元

对每个小问，按下面的九个标签写作：

1. 本问目标和成功指标；
2. 从前一问继承什么，又新增什么；
3. 基线或可检查的简化情形；
4. 机制、变量与目标/约束；
5. 算法接口、步骤、终止和精确/启发式性质；
6. 核心结果表；
7. 一张只解释一个机制的图；
8. 至少一个独立验证口径；
9. 小结：回答本问，说明收益、代价、局限。

### 5.4 论文末部

1. **综合比较**：各方案用统一指标和可行性口径。
2. **稳健性/误差**：参数扰动、数据误差、随机分布和边界情形分开写。
3. **优缺点**：每个缺点对应一条假设、一个已观测失败或一个未验证环节。
4. **结论/建议**：对每问一句最终答案，标注证据性质与适用条件。
5. **支撑材料说明**：给出数据管线、程序入口、图表结果文件和测试位置。

## 6. 可直接用于审稿的结构检查表

### 摘要

- [ ] 每个小问都有方法和结果，不只有模型名。
- [ ] 数字与正文最终结果表一致。
- [ ] 区分观测、模拟、预测、模型内部估计和理论保证。
- [ ] 有一句验证和一句适用范围。

### 模型

- [ ] 问题分析说明了为什么选该模型。
- [ ] 每个假设都有理由和可能影响。
- [ ] 变量、单位、索引和取值域完整。
- [ ] 目标函数和评价指标是同一口径。
- [ ] 后一问增加了哪个状态/约束/不确定性是明确的。

### 算法与代码

- [ ] 正文中的算法有输入、输出、步骤、更新、终止。
- [ ] 说明精确求解、容差最优、启发式或随机搜索的性质。
- [ ] 可穷举的小规模已穷举，启发式已和精确小例子对照。
- [ ] 随机试验有种子、重复次数和分布结果。
- [ ] 图表由结果文件生成，不是手工填数。

### 图表与结果

- [ ] 每张图有唯一论证任务，正文说明看什么。

- [ ] 结论没有超过验证能支持的范围。

## 7. 最终归纳

这 6 篇官方展示论文呈现的不是一个固定目录，而是三种稳定的高分写作能力：

1. **结构映射能力**：每个小问能找到它的分析、模型、算法、结果和小结，后一问对前一问的继承清楚。
2. **证据编排能力**：公式之前有原因，结果之后有解释，结论之外有基线、上界、敏感性、穷举或外部数据中的至少一种检查。
3. **语气校准能力**：能分清“代码输出”、“模型内部预估”、“外部验证”和“最优性保证”，不用好看数字替代证据强度。

其中最值得组合模仿的是：B334 的问题分析、模型家族和上界；B217 的多基线与布局穷举；B044 的模块化仿真与控制变量；B022 的敏感性与反直觉异常解释；B264 的分层优化和统一对照表；B104 的空间图生成特征与视觉叙事。

同时必须记住：官方展示论文也可能有自证循环、随机试验单次运行、伪精确完成率、原始代码占比过高和公式—表格不一致。它们是优秀学习样本，不是不需审查的标准答案。
