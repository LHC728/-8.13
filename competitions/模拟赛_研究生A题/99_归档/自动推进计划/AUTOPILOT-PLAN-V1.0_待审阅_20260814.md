## 2. 自动推进的流转协议（核心变更）

### 2.1 每 Gate 的标准循环

```
冻结任务包（含派单规格、验收命令、检查绑定）
   → E1 主实现 ∥ E2 独立检查器（并行，deepseek-v4-flash / high）
   → RUNNER 集成运行（L1，deepseek-v4-flash / medium）
   → L3 语义验收（独立 D-red 子 agent，deepseek-v4-pro / high）
   → 通过：落 CURRENT_STATE/CHANGELOG，进下一 Gate
   → 不通过：修复后重跑（保留不可变失败证据），连续同类失败升级
```

### 2.2 验收 agent 的独立性保证（关键）

- L3 验收子 agent **只读**：冻结任务包、检查注册表、问题契约、schema、原始输出（response/check_report/日志）、必要参数。**禁止读主实现推理摘要、E1 代码解释、我（主 Agent）的分析笔记。**
- 与主实现异源：验收子 agent 独立复算（复用任务包内嵌 oracle 或独立代码路径），不得导入主模型模块。
- 每 Gate 验收产出：`验收结论 + run_id + 检查逐项状态 + 失败样本 + 证据哈希`，全部落入 `05_结果/` 绑定 run_id 的不可变目录，或按任务包要求落项目管理记录。

### 2.3 派单纪律（SA-V1.0）

每次派单前公开标签表：Agent 名、等级、任务类型、请求模型、reasoning effort、上下文方式、允许读写路径、是否允许下级 agent（默认否）。执行后汇报实际使用清单。本计划不豁免该纪律，只是把"批准→派单"改为"任务包冻结即派单"。

### 2.4 硬停点（唯一需要队伍介入的情形）

自动推进过程中，遇到下列任一情形**立即停止并升级给队伍**，不静默决策：

1. **新歧义**：实现暴露题面/契约未覆盖的状态、边界或冲突；
2. **口径变更需求**：需要改公式、概率语义、状态转移、指标分母、容差、搜索空间或结论强度；
3. **连续失败**：同一 Gate 同类错误修复两次仍失败，或三路对拍/E2 复核连续不通过；
4. **L4 强结论**：最优 K、预防更换阈值、管理建议、论文摘要与结论强度——只提案，必须队伍签字；
5. **成本/预算触线**：账户余额或单日消耗超过本计划第 5 节的预算上限；
6. **最终提交**：论文导出、匿名检查、提交动作，由队伍完成。

除以上六类外，agent 自动继续，不再逐环节等待批准。
