# 检查注册表 V3.1

> `registry_version = CR-V3.1`  
> 生效日期：2026-08-13  
> 状态：第三轮独立评审及队伍重新签字后的当前唯一有效版本。`CR-V3.0` 保留在 `99_归档/旧检查注册表/检查注册表_CR-V3.0.md` 中作为历史证据，不得覆盖或回写。

## 1. 本次版本变化

1. `C02` 的单次无条件差错口径升为题面字面主情景；`C01` 的标准初测—重测链降为关键替代情景。两项检查的数学对象和 ID 不变，只调整主次及失败处置。
2. `C05` 明确：三种 `lambda` 口径相同的是归一来源比例，不是真阳性计数。
3. `C06` 分成“分布不变主命题”和“键控随机带下逐台全等推论”两层。
4. `C07` 增加有限样本经验 `lambda` 的整批聚类不确定性；解析 `lambda` 不报告蒙特卡洛区间。
5. `C08` 增加 3 台、`K=9`、跨班重测的确定性手算时间线。
6. 新增 `C26`，在 G3 正式比较前冻结 H1 预防更换触发式、阈值候选及样本划分。
7. 新增 `C27`，核对题面事实、队伍闭合假设和策略限制的来源分层，并约束创新表述。

## 2. 使用与变更规则

1. 检查必须用 `registry_version + check_id` 唯一引用；只写 `C05` 等裸 ID 不具备跨版本可解释性。
2. 检查 ID 永不复用。后续若改变含义，必须再升版本并保留本文件。
3. 每份验证报告至少记录：版本、ID、状态、实际命令、输入/输出版本、失败样本，以及 `schema/config/code/key/log` 哈希。
4. `硬门`失败时阻断列明的阶段或产物；`H2门`只阻断 H2；统计诊断触发调查，但不得靠反复换种子“刷过”。
5. 主模型与检查器共享同一只读 canonical 参数和 schema；独立的是求根、状态转移、可行性与指标复算代码。
6. G2 不运行 100 台正式实验、不启用 H2、不冻结论文结果数字。
